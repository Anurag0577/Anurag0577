GitHub Profile Stats Generator

Automated statistics display for your GitHub profile README with daily updates via GitHub Actions

GitHub Actions Beginner Friendly ~15 min setup
Security Notice: This guide shows you how to create your own setup. Never share your GitHub Personal Access Token with anyone. Keep it secret in GitHub Secrets only.

What This Does

This project automatically generates and updates statistics on your GitHub profile README, displaying:

  • Total repositories you own and contribute to
  • Total stars across your repositories
  • Total commits you've made
  • Lines of code written (additions and deletions)
  • Follower count

The statistics automatically update daily via GitHub Actions at 04:00 UTC, and display in both light and dark mode SVG files.

Prerequisites

  • A GitHub account
  • Git installed on your computer
  • Python 3.11 or higher installed locally (for testing)
  • Basic command line knowledge

Step-by-Step Setup

1

Fork or Download the Repository

You need to get a copy of the source code. You have two options:

Option A: Fork the repository (Recommended)

  1. Visit the original repository (ask for the link or search for GitHub profile stats generators)
  2. Click the "Fork" button in the top right
  3. This creates a copy under your account

Option B: Download as ZIP

  1. Download the repository as a ZIP file
  2. Extract it to your computer
  3. Create a new repository on GitHub matching your username
  4. Upload all files to your new repository
2

Create Your GitHub Username Repository

GitHub profiles use a special repository that matches your username.

  1. Go to github.com/new
  2. Repository name: Type your exact GitHub username
  3. Make it Public
  4. Check "Add a README file"
  5. Click "Create repository"
The repository name must exactly match your username. For example, if your username is john-doe, create a repository named john-doe.
3

Generate a GitHub Personal Access Token

The token allows the script to read your public GitHub statistics securely.

  1. Go to GitHub Settings → Tokens (Fine-grained)
  2. Click "Generate new token"
  3. Token name: github-stats-generator
  4. Expiration: Choose 90 days or Custom (you'll need to regenerate it later)
  5. Repository access: All repositories

Required Permissions (Account level):

Followers

Read-only access to view follower count

Starring

Read-only access to count repository stars

Required Permissions (Repository level):

Commit statuses

Read-only access to commit data

Contents

Read-only access to repository contents

Metadata

Read-only access to repository metadata

  1. Click "Generate token" at the bottom
  2. Copy the token immediately — you won't see it again!
Critical: Save this token somewhere safe temporarily. You'll add it to GitHub Secrets in the next step. Never commit it to your repository or share it publicly.
4

Add Token to GitHub Secrets

GitHub Secrets keep your token secure and private.

  1. Go to your repository: https://github.com/YOUR_USERNAME/YOUR_USERNAME
  2. Click Settings (top right of your repository)
  3. In the left sidebar: Secrets and variables → Actions
  4. Click "New repository secret"
  5. Name: ACCESS_TOKEN (must be exact)
  6. Secret: Paste your token from step 3
  7. Click "Add secret"
Your token is now safely stored. GitHub Actions can use it, but no one can view it.
5

Clone and Configure the Repository

Download the repository to your computer and customize it.

# Clone your repository
git clone https://github.com/YOUR_USERNAME/YOUR_USERNAME.git
cd YOUR_USERNAME

Edit the following files to customize for yourself:

File: .github/workflows/build.yaml

Change line 36 to your username:

USER_NAME: YOUR_GITHUB_USERNAME

File: today.py

On line 451, change the birthday (optional, for age calculation):

age_data, age_time = perf_counter(daily_readme, datetime.datetime(2002, 7, 5))

Change (2002, 7, 5) to your birth year, month, day, or remove this line if you don't want age displayed.

Files: dark_mode.svg and light_mode.svg

These SVG files contain the visual design. You can customize:

  • Contact information and links (search for placeholder text)
  • Colors and styling (if you know SVG/CSS)
  • Layout and positioning

The script will update the statistics automatically, but static content like your name stays as you set it.

6

Enable GitHub Actions Permissions

Allow the workflow to commit updates back to your repository.

  1. Go to your repository on GitHub
  2. Click Settings
  3. In left sidebar: Actions → General
  4. Scroll to "Workflow permissions"
  5. Select "Read and write permissions"
  6. Check "Allow GitHub Actions to create and approve pull requests"
  7. Click "Save"
7

Test Locally (Optional but Recommended)

Before pushing to GitHub, test that everything works on your computer.

Create a .env file for local testing:

# Copy the example file
cp .env.example .env

# Edit .env with your text editor and add:
ACCESS_TOKEN=your_token_from_step_3
USER_NAME=YOUR_GITHUB_USERNAME

Install dependencies and run:

# Install required Python packages
pip install -r cache/requirements.txt

# Run the script
python today.py

If successful, you'll see:

  • Calculation times for each statistic
  • Total GitHub API calls made
  • Updated dark_mode.svg and light_mode.svg files
Important: Add .env to your .gitignore file to prevent accidentally committing your token!
8

Push to GitHub and Trigger First Run

Upload your customized files and run the workflow.

# Add all changed files
git add .

# Commit with a message
git commit -m "Initial setup for GitHub stats generator"

# Push to your repository
git push origin main

Manually trigger the first workflow run:

  1. Go to your repository on GitHub
  2. Click the "Actions" tab
  3. Select "README build" from the left sidebar
  4. Click "Run workflow" dropdown (right side)
  5. Click the green "Run workflow" button
  6. Wait ~30 seconds and refresh — you should see a green checkmark ✓
If you see a success message, the workflow has automatically updated your stats and committed the changes!
9

Update Your README to Display Stats

Add the generated SVG images to your profile README.

Edit your README.md file and add:

# Your Name

![GitHub Stats](dark_mode.svg#gh-dark-mode-only)
![GitHub Stats](light_mode.svg#gh-light-mode-only)

## About Me
[Your bio and information here]

The #gh-dark-mode-only and #gh-light-mode-only fragments ensure the correct theme displays based on the viewer's GitHub theme preference.

Automation Schedule

Your statistics will automatically update:

  • Daily at 04:00 UTC (scheduled via cron)
  • Every time you push to main branch (on push trigger)
  • Manually via Actions tab (workflow_dispatch)

Troubleshooting

Workflow fails with "Bad credentials"

  • Check that your token is added as ACCESS_TOKEN in GitHub Secrets (exact name)
  • Verify the token hasn't expired
  • Ensure all required permissions were granted when creating the token

Workflow succeeds but no stats appear

  • Check that USER_NAME in .github/workflows/build.yaml matches your username exactly
  • Verify the SVG files were committed (check the latest commit from GitHub-Actions-Bot)
  • Make sure your README.md references the correct SVG file paths

Stats show zero or incorrect values

  • Wait a few minutes after first run — the cache builds incrementally
  • For private repositories: they won't be counted unless your token has private repo access
  • Check that your repositories have commit history (empty repos show zero)

Node.js deprecation warnings

  • These are informational warnings from GitHub Actions
  • They don't cause failures — the workflow has been updated to the latest action versions

Security Best Practices

  • Never commit your .env file to Git
  • Add .env to your .gitignore file
  • Only use GitHub Secrets for storing tokens in CI/CD
  • Use fine-grained tokens with minimal required permissions
  • Set token expiration and regenerate periodically
  • If you accidentally expose a token, revoke it immediately at github.com/settings/tokens

Customization Ideas

  • Edit the SVG files to change colors, fonts, and layout
  • Modify today.py to add or remove statistics
  • Change the cron schedule in build.yaml to update more or less frequently
  • Add badges, links, or additional sections to your README
